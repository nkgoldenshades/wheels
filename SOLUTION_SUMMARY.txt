🔴 THE ERROR YOU'RE SEEING:

    22P02: invalid input syntax for type uuid: "POST_ID_HERE"

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🔍 ROOT CAUSE (You Were Right!):

    Your database has TWO versions of EACH secure function:

    ┌────────────────────────────────────────────────────────────────┐
    │ Function Name              │ UUID Version ❌ │ TEXT Version ✅   │
    ├────────────────────────────┼─────────────────┼──────────────────┤
    │ secure_create_booking      │ EXISTS          │ EXISTS           │
    │ secure_process_payment     │ EXISTS          │ EXISTS           │
    │ secure_generate_otp        │ EXISTS          │ EXISTS           │
    │ secure_verify_otp          │ EXISTS          │ EXISTS           │
    │ secure_process_refund      │ EXISTS          │ EXISTS           │
    └────────────────────────────┴─────────────────┴──────────────────┘

    Postgres always tries UUID version first ← it exists!
    UUID version tries to cast TEXT to UUID ← fails!
    Error returned immediately ← TEXT version never tried

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✅ THE SOLUTION:

    Drop all UUID versions → only TEXT versions remain

    BEFORE:                          AFTER:
    ─────────────────────────────    ──────────────────
    secure_create_booking (UUID)     secure_create_booking (TEXT)
    secure_create_booking (TEXT)  →  ✅ Only one version
                                     ✅ Postgres uses it immediately
                                     ✅ No UUID casting
                                     ✅ Works perfectly
