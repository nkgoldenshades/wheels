# 🔗 UI-Backend Integration Test Guide

## ✅ What Was Fixed

### BookingRepository
- **Before:** Only loaded from local storage (SharedPreferences)
- **After:** Loads from Supabase first, falls back to local storage
- **Query:** Loads bookings where user is customer OR provider

### ReviewRepository
- **Before:** Only synced writes to Supabase, never loaded
- **After:** Loads all reviews from Supabase on init
- **Purpose:** Reviews are public data needed for ratings

---

## 🧪 How to Test

### Test 1: Booking Creation & Sync
1. **Create a booking in the app:**
   - Go to "Find Rides" tab
   - Select a slot
   - Book a seat
   - Complete payment (if enabled)

2. **Verify in Supabase Dashboard:**
   - Open Supabase dashboard
   - Go to Table Editor → `bookings`
   - Find your booking by `id` or `customer_id`
   - Check all fields are populated correctly

3. **Test loading:**
   - Close and restart the app
   - Go to "Requests" tab
   - Verify your booking appears
   - This confirms it loaded from Supabase

### Test 2: Review Creation & Sync
1. **Complete a booking:**
   - Provider accepts booking
   - Provider verifies OTP
   - Booking status = completed

2. **Leave a review:**
   - Go to completed booking
   - Tap "Leave Review"
   - Rate and submit

3. **Verify in Supabase Dashboard:**
   - Go to Table Editor → `reviews`
   - Find your review by `booking_id`
   - Check rating and comment

4. **Test loading:**
   - Close and restart the app
   - Go to provider's profile
   - Verify rating shows correctly
   - This confirms reviews loaded from Supabase

### Test 3: Multi-Device Sync
1. **Device A:** Create a booking
2. **Device B:** Login with same account
3. **Device B:** Check "Requests" tab
4. **Expected:** Booking appears on Device B (loaded from Supabase)

### Test 4: Offline → Online Sync
1. **Go offline** (airplane mode)
2. **Create a booking** (saves to local storage only)
3. **Go online**
4. **Restart app**
5. **Expected:** Booking syncs to Supabase and appears in dashboard

## 🐛 Common Issues

### Issue: Bookings not appearing after restart
**Cause:** Supabase RLS policy blocking access
**Fix:** Check that `bookings` table has policies for:
- `user_id.eq.{current_user_id}`
- `provider_id.eq.{current_user_id}`

### Issue: Reviews not loading
**Cause:** RLS policy too restrictive
**Fix:** Reviews should be publicly readable (for ratings)

### Issue: "No user logged in" error
**Cause:** Repository initializing before Firebase Auth
**Fix:** Already fixed in `main.dart` - Firebase initializes first

## 📊 Expected Data Flow

### App Startup:
```
1. Firebase initializes
2. AuthRepository initializes
3. Repositories initialize:
   - BookingRepository._loadFromSupabase()
   - ReviewRepository._loadFromSupabase()
   - VehicleRepository._loadFromSupabase()
   - SlotRepository._loadFromSupabase()
   - UserPostRepository._loadFromSupabase()
4. UI renders with Supabase data
```

### Creating a Booking:
```
1. User taps "Book"
2. BookingRepository.createBooking()
3. Booking saved to local storage
4. _syncBookingToSupabase() called
5. Booking inserted to Supabase
6. OTP generated by Supabase trigger
7. OTP returned and saved locally
8. UI updates
```

### Loading Bookings:
```
1. App starts
2. BookingRepository.init()
3. _load() called
4. _loadFromSupabase() queries:
   - WHERE user_id = current_user OR provider_id = current_user
5. Bookings loaded and saved to local storage
6. UI displays bookings
```
