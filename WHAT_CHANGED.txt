FILE 1: lib/services/vehicle_repository.dart
─────────────────────────────────────────────────────────────────────────────

PROBLEM:
  The _loadVehicles() method was loading ALL provider vehicles from database,
  then filtering client-side by userId. This failed because the loaded vehicles
  were from OTHER users, causing an empty list.

SOLUTION:
  Added database-level filtering to only load the current user's vehicles:

  BEFORE:
    final response = await _supabase
        .from('vehicles')
        .select('...')
        .eq('vehicle_owner', 'provider')
        .order('created_at', ascending: false);

  AFTER:
    final currentUser = AuthRepository.instance.currentUser;
    if (currentUser == null) {
      _vehicles.value = [];
      return;
    }
    final response = await _supabase
        .from('vehicles')
        .select('...')
        .eq('vehicle_owner', 'provider')
        .eq('profile_id', currentUser.id)  ← NEW: Filter at DB level
        .order('created_at', ascending: false);

RESULT:
  ✅ Only current user's vehicles are loaded
  ✅ No need for client-side filtering
  ✅ More efficient (filter happens at database)

───────────────────────────────────────────────────────────────────────────────

PROBLEM:
  The userVehicles getter was doing client-side filtering that was redundant
  and added unnecessary complexity.

SOLUTION:
  Simplified it since filtering now happens at database level:

  BEFORE:
    List<Vehicle> get userVehicles {
      final currentUser = AuthRepository.instance.currentUser;
      if (currentUser == null) return [];
      final filtered = _vehicles.value
          .where((v) => v.userId == currentUser.id)
          .toList();
      debugPrint('🔍 userVehicles filter:');
      debugPrint('   Current user ID: ${currentUser.id}');
      // ... lots of debug code
      return filtered;
    }

  AFTER:
    List<Vehicle> get userVehicles {
      // Vehicles are already filtered by profile_id in _loadVehicles()
      debugPrint(
        '🔍 userVehicles: Returning ${_vehicles.value.length} vehicles (pre-filtered by profile_id)',
      );
      return _vehicles.value;
    }

RESULT:
  ✅ Cleaner code
  ✅ Fewer debug logs
  ✅ Same functionality

FILE 2: lib/services/slot_repository.dart
─────────────────────────────────────────────────────────────────────────────

PROBLEM:
  When clicking a vehicle to view its details, the app calls
  getAllSlotsForVehicle() to load the list of posts for that vehicle.
  This query had NO TIMEOUT, so if it was slow or hit an issue, it would
  hang indefinitely.

SOLUTION:
  Added 10-second timeout to the query:

  BEFORE:
    Future<List<SlotEntry>> getAllSlotsForVehicle(String vehicleId) async {
      try {
        final supabase = Supabase.instance.client;
        final response = await supabase
            .from('posts')
            .select('*')
            .eq('vehicle_id', vehicleId)
            .or('post_type.eq.offer,post_type.is.null')
            .order('created_at', ascending: false);
        // ... rest of method
      }
    }

  AFTER:
    Future<List<SlotEntry>> getAllSlotsForVehicle(String vehicleId) async {
      try {
        final supabase = Supabase.instance.client;
        debugPrint('🔍 getAllSlotsForVehicle: Starting fetch for vehicleId=$vehicleId');
        
        final response = await supabase
            .from('posts')
            .select('*')
            .eq('vehicle_id', vehicleId)
            .or('post_type.eq.offer,post_type.is.null')
            .order('created_at', ascending: false)
            .timeout(const Duration(seconds: 10));  ← NEW: 10-second timeout
        
        debugPrint('🔍 getAllSlotsForVehicle: Query returned ${response.length} slots');
        // ... rest of method
      }
    }

RESULT:
  ✅ If query takes > 10 seconds, it times out gracefully
  ✅ App doesn't hang indefinitely
  ✅ Better debug logs to track what's happening

ISSUE #1: Vehicle List Empty
──────────────────────────────

BEFORE:

  ❌ See "No services added yet" (list is empty)
  ❌ Vehicle count shows 0

ISSUE #2: Vehicle Detail Screen Hangs
──────────────────────────────────────

BEFORE:
  ❌ Click on a vehicle
  ❌ Loading spinner appears
  ❌ Spinner keeps spinning... forever
  ❌ App appears frozen (must force close)
  ❌ No error message (just hangs)

ROOT CAUSE:
  getAllSlotsForVehicle() query has NO TIMEOUT
  If the query is slow or fails, it waits forever
  User sees infinite loading spinner

AFTER:
  ✅ Click on a vehicle
  ✅ Loading spinner appears briefly
  ✅ Details load in < 2 seconds
  ✅ See list of posts (or "No services added yet")
  ✅ If query takes > 10 seconds, gracefully returns empty

FIX:
  Added .timeout(const Duration(seconds: 10)) to query
  Query must complete within 10 seconds or times out
  Returns empty list on timeout (no hang)
